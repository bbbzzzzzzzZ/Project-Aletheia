# Aletheia Architecture Map

本架构的方向已经由项目发起者确认；模块的现实效果和实施形式仍待验证。

## 项目定位

Aletheia 不是一套已经完成的法典。它先说明项目怎样看人和共同生活；只有某件事另行显示出共同协调的必要，才研究有限任务或规则怎样成立，并由反馈、责任与退出持续修正。

## 四个阅读层次

1. **世界观**：具体的人、关系、共同生活条件与制度工具分别处在什么位置；这里没有处理流程。
2. **规范地基与模型**：基本权利、基本保障、人的持续修订权、需求归属、责任、权力、资源、决定与反馈边界。
3. **按条件使用的制度生成语法**：只处理已经独立说明的候选共同协调事项，区分任务、规则、承担依据与有限授权。
4. **应用与验证**：宪制司法、行政、财政、信息与 AI、激励、劳动、教育、经济和政治模块；全部接受压力测试。

## 世界观与制度语法之间没有默认箭头

```text
世界观 ──约束──→ 第一原则与各模型
  │
  └─ 人的经验与关系问题可以停留在理解、自主行动、关系调整或自愿合作

候选共同协调事项
  └─ 必须另行证明共同影响、权利保护、公共资源、持续风险或结构化协作需要
      └─ 通过入口审查后，才按条件使用制度生成语法
```

人的经验被表达，不会因此成为候选共同协调事项。候选事项也不自动成为共同规则、具体任务、个人义务或执行权限；“不介入、继续理解或沿用无需新增任务与规则的回应”是正常结果。

## 共同协调成立后的闭环

共同事项只有越过入口门槛后，才进入方案比较、受影响者参与、资源审查、暂时决定、有限执行、结果反馈和复核。期间的信息、资源、责任与权限不能汇聚成不可挑战的单一中心；掌握资源、数据、专业能力或贡献记录，不自动取得最终决定权。

具体任务与共同规则分属两个循环。规则可以提供任务成立条件，任务结果可以触发规则复核；二者都不能替另一方完成授权，也必须允许暂停、救济、修正和退出。

## 模块分工

- 宪制与司法：规定不可逾越的底线、权力来源、解释边界和救济。
- 民主与代表：形成共同目标和公共授权，不得取消基本主体地位。
- 行政：接受任务授权并执行，不定义自己的永久目的。
- 财政：为已授权任务配置资源，预算不自行产生目的。
- 信息与 AI：提供可质疑的事实材料和建议，不垄断解释与裁决。
- 激励：奖励具体行为，不生成公民等级、人格等级或政治特权。
- 劳动等应用模块：把上游原则放入具体情境验证，不反向改写基本权利。

## 当前边界

这张图说明阅读层次和接口，不证明任何问题都应制度化，也不证明各模块已经可实施。具体制度仍须完成入口论证、证据研究、受影响者参与、法律审查、原型试验和停止条件。
