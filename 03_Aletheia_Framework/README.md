# 03 · Aletheia 核心框架

本目录保存项目对根问题的当前答案。它是后续制度设计的上游约束，但仍处于可评审、可修订的 `0.x` 阶段。

## 文档关系

```text
世界观 ── 人、关系、社会与制度处在什么位置；这里没有处理流程
  └─约束→ 第一原则
      ├── 需求模型 ── 谁的需求、如何表达、如何成为共同需求
      ├── 需求归属与公共需求责任 ── 需求归谁、谁负第一责任，以及为何不自动派工
      ├── 责任模型 ── 谁对个人需求、条件、判断、执行、有限互惠、影响与修复负责
      ├── 权力模型 ── 基本权利、事实权力与授权权限怎样区分，权限何时退出
      ├── 资源模型 ── 资源权利束及即时救济、预防、长期能力与象征投入如何分账
      ├── 决策模型 ── 受影响者共同设计，并与代表、专家和执行者形成可修订决定
      └── 反馈修正机制 ── 如何发现错误、申诉、补偿、撤权与学习

候选共同协调事项 ── 必须另行说明为何不能停留在理解、自主行动、关系调整或自愿协作
  └─按条件使用→ 制度生成语法 ── 任务与共同规则怎样有限成立、复核和退出

研究与推理方法 ── 约束上述命题怎样由证据、反例和修订形成
```

## 世界观在流程之前

[`世界观.md`](世界观.md) 只回答项目怎样看待具体的人、人与人的关系、共同生活形成的社会条件，以及制度为什么只是有限工具。它明确保留倾听、理解、暂停、本人行动、关系调整、私人帮助和自愿合作等无需新建共同任务或规则的回应空间。

人的困惑、痛苦、愿望或需要被表达，不会因此成为公共事项。研究可以停在人的经验和关系层；没有形成任务或新制度不是失败。世界观对所有下游研究构成边界，但它本身不是制度生成语法的输入端。

## 制度生成语法的使用范围

[`制度生成语法.md`](制度生成语法.md) 只在某件事已经被独立说明为候选共同协调事项时使用。进入前必须解释为什么理解、本人行动、关系调整、私人或自愿协作、既有服务与权利救济仍不足，且为什么重复、结构性、跨主体或高后果影响确需共同协调。

进入语法仍不等于任务或规则已经成立。语法内部区分一次具体行动的任务生命周期与重复问题的制度形成和修正循环；规则可以约束任务成立条件，任务证据可以触发规则复核，但任何一方都不能替另一方完成决定、承担依据、授权、申诉或退出。

项目已确认：公共需求经正当程序成立后，公众第一责任随需求归属成立；这不能被解释为每名公众成员承担相同任务，也不能停在“社会负责”的口号，必须继续落到可追溯的共同决定和机构职责。项目也接受具备现实能力的成员原则上承担有约束力但有限的互惠公共责任。公众第一责任不自动确定组织形式、一般互惠责任、具体任务或权限。普通自愿任务以本人知情承诺为前提；有约束力公共责任任务必须走独立分配分支，逐项满足机构先行、公平、能力、合理条件、替代、豁免、延期和申诉要求。紧急例外继续单独处理。

项目同时接受个人需求责任与非等级互助：对于归属于个人的需求，个人在现实能力与安全允许范围内积极参与解决，不把能够合理承担的部分全部外包；公共需求、组织需求、机构失败和侵害后果则不能因发生在某个人身上就改写成他的个人责任。两者都不取消基本权利，不免除机构和侵害者责任，也不建立逐人功劳结算、感恩服从或固定强弱身份。

《世界观》保存项目对人和共同生活的基本方向；《制度生成语法》保存达到入口门槛后才使用的任务与规则语法；《研究与推理方法》约束命题如何产生和修订；《第一原则》与各模型保存当前答案。方法不能替原则作价值决定，原则也不能豁免自己接受证据和反例审查。
