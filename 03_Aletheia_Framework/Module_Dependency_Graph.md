# Module Dependency Graph

本依赖关系已经作为项目方向接受；后续压力测试可以通过正式修订调整它，但不得静默改写。

```text
理论定义依赖（不表示个人事项被送入流程）：

世界观 ──约束──→ 第一原则 / 术语基线
  ├─→ 根问题与人类行为假设
  └─→ 需求、责任、权力、资源、决策与反馈模型

第一原则 / 术语基线
  ├─→ 需求模型 ──概念约束──→ 决策模型 ──概念约束──→ 民主与代表
  ├─→ 需求归属与公共需求责任 ──概念约束──→ 责任模型 / 公共责任制度
  ├─→ 权力模型 ──概念约束──→ 宪制司法 ──概念约束──→ 行政授权
  ├─→ 责任模型 ───────────────────────────→ 审计与救济
  └─→ 资源模型 ──概念约束──→ 公共财政 ──概念约束──→ 任务预算

事项运行入口（与上述理论依赖分开）：

另行成立的候选共同协调事项
  └─→ 入口审查 ─→ 制度生成语法

公共信息宪政 ─→ 民主 / 行政 / 财政 / 司法
AI 治理 ─────→ 仅辅助上述模块，不取得最终授权

制度生成语法 + 行政授权 + 任务预算 + 信息依据
  └─→ 劳动 / 教育 / 经济 / 政治等应用模块

所有模块 ─→ 压力测试 ─→ 反馈修正 ─→ 再授权或退出
```

## 依赖规则

1. 下游模块可以发现上游问题，但不能静默改写上游原则。
2. 专业事实判断不替代价值决定；民主决定不替代事实核查。
3. 预算、数据、算法、能力和贡献记录都不能自行生成授权。
4. 紧急权限只能由预先规定的规则触发，并自动进入复核与回收流程。
5. 人的经验、困惑、关系冲突或需要不因存在或被表达，就成为制度生成语法的输入；理解、自主行动、关系调整、自愿合作和不介入必须保持为正常路径。
6. 候选共同协调事项、共同规则、具体任务、个人承担依据与执行权限必须分别成立，不能沿依赖箭头自动跳转。
7. 需求体验、表达、归属、组织承接与具体执行必须分别判断；公共需求由公众负第一责任，不从依赖关系直接生成任何成员任务。

现行入口分别见 [`世界观.md`](世界观.md)、[`需求归属与公共需求责任.md`](需求归属与公共需求责任.md) 与 [`制度生成语法.md`](制度生成语法.md)。
