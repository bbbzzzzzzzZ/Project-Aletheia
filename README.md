# Project Aletheia

> **Project Aletheia 是一个关于“人类如何从需求出发，通过责任建立自由共同体”的制度哲学研究项目。**

`Aletheia` 取自希腊语 `ἀλήθεια`。本项目借用“揭示 / 去蔽”的意象：不是替人规定应当如何生活，而是研究人如何认识自己的需求、如何形成共同需求，以及制度如何让需求、责任与权力保持一致。

它把自身定位为一项“文明操作系统”的基础研究，而不是一部从具体制度开始的社会法典。

当前工作版本：`0.2.7`（责任积分与有限互惠机制整合）  
更新日期：`2026-08-16`

## 项目研究什么

项目的起点不是某一种制度，而是两条互相约束的轴：

```text
目的与层级轴：人 → 关系 → 社会 → 制度

制度形成与修正循环：问题进入 → 受影响者识别 → 方案与公共决定
                    → 有限试验 → 监督与复核 → 修订 / 暂停 / 废止

任务生命周期：需求说明 → 条件与公共性审查 → 任务形成
              ├─ 普通任务：邀请与承诺
              └─ 公共责任任务：个案义务分配（适配、豁免、申诉等条件齐备）
              → 有限授权 → 执行 → 交接 / 退出 / 修复
```

目的与层级轴说明制度为什么必须回到具体的人及其关系；制度形成与修正循环和任务生命周期分别说明公共规则怎样形成、具体任务怎样取得承担依据和有限权限。普通任务以本人承诺为承担依据；公共责任任务只有经过事项适配程序并具备豁免、替代和申诉等条件，才可能形成个案义务。两条循环相互反馈，但任何一步都不能自动替另一条循环完成授权。完整说明见 [`03_Aletheia_Framework/世界观与制度生成语法.md`](03_Aletheia_Framework/世界观与制度生成语法.md)。

核心问题是：

> 谁的需求被表达？谁能代表它？谁承担满足需求的成本和影响？谁因此获得何种权限？这些权限何时退出？

## 项目不是什么

- 不是一套已经完成、等待执行的社会蓝图；
- 不是以某位哲学家或某种意识形态为权威的注释工程；
- 不是用“公共利益”替每个人定义幸福；
- 不是把劳动、贡献、能力或积分变成人格等级；
- 不是完整法典、参数表或调度算法。

## 当前第一原则摘要

1. 人的存在价值先于职业、劳动、能力和贡献。
   人是能够终身学习并修订方向的开放主体，但这不产生被迫持续优化的义务。
2. 本人是自身需求的第一表述者；帮助、专业与代理都不能取得其终极生活目的的所有权。
3. 需求天然具有表达、说明、请求协作和自主追求的资格，但不自动产生支配他人或调用公共资源的授权权限。
4. 个人进入需求满足方案后，应在能力、安全和现实条件允许范围内合理自助、求助、维权、配合与减损；但个人需求责任不取消基本权利，也不免除侵害者和机构责任。
5. 责任还来自请求、承诺、明确角色、判断、共同决定、授权、行动与实际影响；公共必要性、机构维护责任和具体个人任务不得自动跳转。
6. 具备相应现实能力的成员，原则上对维持公共必要条件承担有约束力但有限、公平且可审查的互惠公共责任；正当理由可以支持豁免、延期或替代。
7. 能力只构成具体任务分配的必要条件之一，不决定人的价值，也不意味着登记后可被自动派工或随时调用。
8. 任务权限在共同任务、责任、能力和正当授权成立后产生，受任务限定、可监督并随任务退出。
9. 个人时间默认属于自己；有限互惠公共责任不能扩张为共同体对个人全部时间、身体或人生方向的所有权。
10. 基本保障和基本权利不与履责挂钩，也不因逃避责任而消失。
11. 衰老、疾病、残障、失能和照护需要属于共同脆弱处境；互助在平等主体之间跨时间和对象传递，不作逐人功劳结算，也不制造感恩服从。
12. 高于基本保障底线、与公共协作直接相关的互惠性公共运行权益，可以在严格相关、相称、限期、可申诉并具有恢复程序时与履责相关；具体清单与后果仍待研究。
13. 任何制度都不得替他人定义唯一正确的幸福、人生目标或身份。
14. 学习、训练和资格验证入口原则上开放；专业资格不因固定岗位名额限量，岗位与具体任务权限另行成立。
15. 每个人的生命、身体完整、性自主和现实人身安全属于最高保护层级，但责任与刑罚仍须依行为、证据、程序和相称性分别判断。
16. 生育、婚姻、亲职和儿童权利不得相互自动推出；儿童不是父母或国家的所有物，公共育幼分担照护而不取代稳定关系。
17. 公共权力不得同时控制决定、证据、监督、修复与利益；正常监督失效后须保留外部证据、替代调查和先行修复等纠错入口。
18. 合作应通过改善需求、时间、安全、服务和现实补偿而值得选择；年度责任积分用于当期公平结算，领域贡献积分长期累计，质量评价与专业参考摘要保持领域限定，均不得转化为人格等级、基本权利差异或跨领域权限。
19. 公共事项须按议题、信息、方案、预算、执行、质量、投诉、监督、调查与责任认定及贯穿式重大利益绘制控制图；集中达到触发条件时自动进入回避、复核、审计或拆分。

完整表述见 [`03_Aletheia_Framework/第一原则.md`](03_Aletheia_Framework/第一原则.md)。

## 制度文档内部的三级结构

制度设计文档采用三级结构，禁止混写；它不同于上文的三条成果轨道：

1. **框架层**：说明为什么设计、原则是什么、模块如何连接、哪些问题未决。
2. **机制层**：说明流程、角色、授权、监督、申诉和退出。
3. **实施层**：保存算法、比例、时长、金额、表单和法条。

根目录与 `03_Aletheia_Framework/` 只保留框架层内容。具体参数不得仅因曾在讨论中出现，就升级为第一原则。

## 三类并行产出

项目同时维护三类产出，而不是等一类彻底完成后才开始下一类：

根目录治理采用明确分工：[`DECISION_LOG.md`](DECISION_LOG.md) 记录已接受决定和确认范围，[`GLOSSARY.md`](GLOSSARY.md) 维护当前术语，[`DOCUMENT_STATUS.md`](DOCUMENT_STATUS.md) 维护引用资格与成熟度，`03_Aletheia_Framework/` 维护理论命题、理由、证据和反例。它们共同构成治理基线，但不能互相代替。三条成果轨道均不得越过这些入口。

1. **研究框架**（`00`—`03`）：保存当前理论问题、命题、理由和反例，并接受根治理基线约束；
2. **思想书**（`07_Writing/Thought_Book/`）：用日常语言说明为什么提出这些问题；
3. **制度白皮书**（`04_Institution_Design/`）：说明原则怎样转化为制度模块和接口。

另有 [`07_Writing/Project_Overview/`](07_Writing/Project_Overview/) 用于形成三条轨道共同使用的简要项目总纲；它是导航性派生稿，不是第四条成果轨道。

三者可以互相发现问题，但不能各自生成互不兼容的定义。新命题须先回到研究框架评审；一旦接受，再同步根治理基线、白皮书与思想书。

## 文档状态

每份文件顶部使用统一的 `status`：

| 状态 | 含义 |
|---|---|
| `stable` | 当前基线，可被后续文档引用；仍允许通过正式变更修订 |
| `draft` | 已有方向，但论证或边界未闭合 |
| `question` | 主要答案仍开放；可以重述已经接受的边界，但文件中的新增方案不代表项目主张 |
| `template` | 写作或分析模板，尚无实质结论 |
| `archive` | 历史记录，不得作为现行定义引用 |

状态总览见 [`DOCUMENT_STATUS.md`](DOCUMENT_STATUS.md)。

## 当前研究边界

当前优先工作不是继续扩写制度细则，而是：

1. 锁定第一原则的可反驳版本；
2. 区分个人需求、共同需求与被代表的需求；
3. 检验个人需求责任中合理自助、渠道可及、机构独立责任与紧急救助的边界，防止把积极承担偷换成对困境者的单方归责；
4. 保持公共必要性认定、公共组织与维护责任、有限互惠公共责任和具体任务义务分层；接受有限互惠原则，但不得由公共缺口、成员身份或能力登记自动派工；
5. 区分基本权利、显著或持续的非对称事实权力与授权权限，并分别审查其边界；基本权利包含必要的程序资格；
6. 建立“不得替他人定义幸福”的程序性保障；
7. 研究具体工时、任务分配、正当理由、豁免或替代、最小记录、申诉和恢复机制；
8. 界定哪些互惠性公共运行权益可以与何种履责直接相关，同时确保基本保障和基本权利不被包装为条件性权益；
9. 用医疗、维权、残障、养老和长期照护案例检验非等级互助、贡献承认与基本照护不计功怎样同时成立，再用劳动、教育、知识与治理制度继续压力测试。
