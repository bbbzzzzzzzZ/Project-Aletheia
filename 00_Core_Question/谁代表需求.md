# 谁代表需求？

这是 Project Aletheia 当前最关键的开放问题之一。

## 起点

本人对自身需求经验和终极生活目的拥有优先表述、解释、修订和撤回资格；这种优先性不等于本人垄断外部事实、对他人的影响或公共资源判断。大规模共同决策、儿童与失能者保护、未来世代、生态系统和紧急情境仍使代理与代表不可避免。

## 需求者与受影响者不是同一角色

同一事项至少应区分：需求体验者、议题或方案提议者、直接受益者、直接负担承担者、第三方受影响者、无法直接发声者与执行者。一个人可以同时处于多个位置，但不能用“需求者”一词抹去其他位置的不同资格和责任。

共同方案不以找到“全部受影响者”或取得全体一致为前提。程序应：

1. 识别在现有信息和合理努力下可发现的、受到实质影响的个人与群体；
2. 提供与影响程度、不可逆性和负担集中度相称的无障碍信息、表达、共同设计、异议和救济机会；
3. 公开仍未被识别、无法参与或存在代表争议的范围；
4. 依据事前说明、与事项相适配的程序形成暂时决定，并保留少数保护、理由、复核和修正。

参与不等于每位参与者拥有总体决定权，也不表示全体必须一致。基本权利损害、不可逆风险或负担高度集中时，应提高必要性证明、同意或保护、补偿与复核门槛，而不是让较强势的需求者或多数自动越过受影响者。

## 任何候选代表机制都必须回答

以下清单用于检验候选答案，不在本问题文件中预先确定唯一代表制度。当前模型见 [`../03_Aletheia_Framework/决策模型.md`](../03_Aletheia_Framework/决策模型.md)，应用层见 [`../04_Institution_Design/Political_System/代表机制.md`](../04_Institution_Design/Political_System/代表机制.md)。

| 条件 | 必须回答的问题 |
|---|---|
| 对象 | 代表谁，谁明确不在代表范围内？ |
| 事项 | 代表的是信息传递、目标形成、谈判还是最终决定？ |
| 授权 | 授权如何产生；无法直接授权时依据什么保护原则？ |
| 期限 | 何时到期，能否续期？ |
| 信息 | 代表者必须向被代表者公开什么？ |
| 纠正 | 被误述、忽略或情况变化时如何修正？ |
| 撤回 | 谁能撤回，撤回成本是否真实可承受？ |
| 责任 | 错误代表、利益冲突或越权由谁承担后果？ |

## 四类定义活动

“谁定义”必须按对象拆开：

| 定义活动 | 主要资格或角色 | 边界 |
|---|---|---|
| 表述个人需求经验与终极生活目的 | 本人；确需代理时由受约束代理协助 | 代理不取得需求所有权；事实和外部影响仍可质疑 |
| 暂时形成共同问题、目标与可接受取舍 | 合理可发现的实质受影响群体参与，由事项适配的正当程序作出公共决定 | 不等于全体一致，不以专业能力剥夺参与，也不让需求者单方决定他人负担 |
| 判断事实、风险、因果与方案可行性 | 具备相关知识者提出可说明、可复核的专业判断，接受公众与同行质疑 | 专家不能“定义事实”或垄断共同目标；不确定性和利益冲突必须公开 |
| 制定分类、资格、指标与数据用途 | 经授权的程序在受影响者和相关专业人员参与下制定，并接受独立审计 | 管理机构不能以控制数据和指标自行证明正当性，指标不得跨域静默使用 |

## 防止“代言夺权”

- 代表需求不等于拥有需求。
- 能更清楚表达，不等于更有权替他人决定。
- 专业知识可以约束手段判断；善意、爱、照护、专业或历史正义本身均不构成授权。本人能够表达时，应先询问而非替其选择；无法表达时按下文最小替代判断处理。
- 多数票不能自动证明少数者的需要不存在。
- 数据模型只能提示模式，不能成为人的唯一代理。

## 特殊情形

- 无法表达者：采用最小替代判断、最大利益冲突披露和定期复核。
- 未来世代：代表者必须说明不可逆风险和不确定性，而非声称获得了未来人的同意。
- 生态与非人生命：明确这是人类承担的保护责任及价值判断，不伪称其已直接授权。
- 紧急状态：临时代理必须有更短期限、更强记录和自动失效。
- 具有共同可达需求的群体：共享某种障碍不等于需求同质；社区治理必须同时保留直接表达、少数意见、多重身份、服务更换和个人退出。应用草案见 [`../04_Institution_Design/Shared_Mechanisms/主体社区与城市渐进可达机制.md`](../04_Institution_Design/Shared_Mechanisms/主体社区与城市渐进可达机制.md)。
