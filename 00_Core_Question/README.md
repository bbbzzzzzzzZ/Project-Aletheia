# 00 · 核心问题

本目录保存项目不能绕过、也不应被过早封闭的问题。每份文件可以记录问题边界、竞争路线和当前回答的导航摘要，但不是规范答案的权威来源；完整回答只在 `03_Aletheia_Framework/` 维护，发生冲突时以该处逐文件状态为准。

## 七个根问题

1. [`人是什么.md`](人是什么.md)：制度面对的是身份、劳动力，还是能形成并修订生活方向的人？
2. [`人为什么合作.md`](人为什么合作.md)：合作如何从相互依赖产生，又为何不必然等于服从？
3. [`人真正需要什么.md`](人真正需要什么.md)：谁有权认识、表达、解释和修订需求？
4. [`需求与责任.md`](需求与责任.md)：有限互惠公共责任已经被原则性接受后，公共必要性、机构维护与具体任务义务怎样分别成立，避免自动派工？
5. [`谁代表需求.md`](谁代表需求.md)：本人无法直接表达或共同决策不可避免时，代表如何获得并失去授权？
6. [`权力与责任.md`](权力与责任.md)：完成责任所需的权限如何避免变成永久支配？
7. [`自由与共同体.md`](自由与共同体.md)：自由如何在相互依赖中成立，而不是被共同体吞没？

## 使用规则

- 每个制度文档至少链接一个根问题。
- 新答案必须区分：规范主张、经验假设、机制设计和实施参数。
- 不能因为问题难以回答，就由专家、代表、算法或多数替当事人定义需求。
- 不能因为强调个人自主，就忽略行为对他人和共同条件造成的影响。
- 不能以履责表现取消食物、住所、基础医疗、教育、人身安全和必要服务等基本保障；也不能把对逃避责任行为的批评固定为人格身份。

## 与六个第一原则形成问题的映射

本目录的七个根问题负责持续提出问题；[`../03_Aletheia_Framework/第一原则.md`](../03_Aletheia_Framework/第一原则.md) 中的六个形成问题负责说明当前规范答案从哪里开始。两份清单用途不同，不要求一一对应：

| 七个根问题 | 主要进入的形成问题 | 说明 |
|---|---|---|
| 人是什么 | 1 人的基本单位 | 同时由开放主体的人类模型接受经验检验 |
| 人为什么合作 | 3 责任从哪里产生、4 授权权限为什么存在 | 合作原因主要是经验问题，不能由第一原则预先宣布；规范框架只处理合作怎样形成责任和权限 |
| 人真正需要什么 | 2 需求的初始资格、5 谁表述需求、6 如何防止代替他人定义幸福 | 区分主体经验、需求解释、满足方案与公共正当性 |
| 需求与责任 | 2 需求的初始资格、3 责任从哪里产生 | 区分已接受的有限互惠公共责任与须逐项成立的具体任务义务，防止自动派工 |
| 谁代表需求 | 5 谁表述需求、6 如何防止代替他人定义幸福 | 代表、代理和共同决定须分别说明范围与纠正方式 |
| 权力与责任 | 3 责任从哪里产生、4 授权权限为什么存在、6 如何限制代言和支配 | 另须识别未经授权但实际存在的事实权力 |
| 自由与共同体 | 1 人的基本单位、3 责任边界、4 公共权限、6 多元生活 | 同时处理有限互惠责任、时间主权、无条件基本保障与非基本互惠性公共运行权益的边界 |

“六个形成问题”不是对“七个根问题”的删减；它们只是第一原则文件组织当前答案的方式。
