# 五个候选机制内部走查

## 这组文件是什么

本目录用完全假设的场景检查 [`五个候选机制交叉表`](../../04_Institution_Design/Project_Aletheia_五机制交叉表.md) 能否阻止以下跳跃：

```text
有需要
≠ 已经是公共需求
≠ 已经有具体任务
≠ 某个人已经必须承担
≠ 承担者已经取得执行权限
```

三份走查都不是现实案例、专业意见、模拟实验或验证记录，因此不放入 `08_Research_Workbench/07_Validation_Records/`。文中的人员、机构、容量、风险、法律和专业条件都是待核验假设，不得用来派工、授权或制定现实参数。

## 内部结果词表

| 结果 | 只表示什么 | 不表示什么 |
|---|---|---|
| **可继续准备外部验证** | 在当前假设下，输入、输出和返回路径能被分别记录 | 不表示现实可行、公平、安全或合法 |
| **退回上游** | 前置认定、机构责任、资源、任务或授权依据不足 | 不表示相应公共需要不存在 |
| **触发停止** | 已越过共同停止线或领域安全底线 | 不表示所有相邻方案都必须终止 |
| **信息不足** | 没有足够事实选择方案或形成判断 | 不允许用直觉、职业身份或机构自证填空 |

任何一种内部结果都不能写成“走查通过”或 `validated`。只有形成明确验证对象、材料或参与者、方法、失败条件和记录协议后，才能讨论 `ready-for-validation`；只有现实材料或参与真正进入，才可能进入后续验证状态。

## 每份走查必须保留的字段

- 场景假设与明确未知；
- 受影响者、承担者、机构和利益冲突；
- 公共必要性认定的“接受／否定／延期补证”；
- 公共决定、具体责任分配和执行授权三类输出；
- 五个机制的输入、输出、停止线与返回路径；
- 至少一个反例；
- 所需现实证据与不可由 AI 替代的参与者；
- 内部结果及其验证边界。
