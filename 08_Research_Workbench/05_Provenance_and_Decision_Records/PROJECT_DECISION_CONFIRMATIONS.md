# Project Decision Confirmations

本文件记录 Project Aletheia 自身的方向决定由谁、基于什么来源、在什么范围内得到确认。它不复制完整私人对话，也不把项目发起者的确认冒充为现实公共决定、受影响者同意或制度实施授权。

### 被确认的六步范围

1. 区分基本权利、事实权力与授权权限，基本权利包含必要的程序资格；避免把现实控制力或权利资格直接当成任务权限，事实权力限于显著或持续的非对称实际控制。
2. 区分公共必要性认定、公共组织与维护责任与个人公共义务；前两者进入分析结构，第三项是否成立继续开放研究。
3. 区分具体任务生命周期和制度形成与修正循环，不让一次任务或一次制度决定自动推出另一方已经正当。
4. 明确退出、需求者、受影响者与定义权角色，并区分“项目决定确认记录”和“候选公共决策留痕”。
5. 将基本保障、个人时间与公共服务连续性如何兼容单独列为 `question`，不预写结论。
6. 在内容形成后完成导航、命名、状态、版本、变更日志和校验；经本轮治理审查进一步明确，Source ID、确认记录与语义变更草稿必须前置，压缩与最终校验后置。

### 确认边界

- 该确认接受上述分类、接口与工作顺序，不确认任何尚未写出的实施参数、强制义务、公共机构或裁决程序。
- 对第 2 步的确认不等于接受“个人公共义务已经成立”。
- 对第 5 步的确认只授权建立问题，不授权把候选回答写成项目结论。
- “按照这个修改”只覆盖上述六步及其必要治理落地，不表示项目发起者逐句确认后续 AI 扩写。
- 本记录只适用于 Project Aletheia 内部版本治理，不是公众、受影响者、未来制度成员或专业机构的授权。

## 与公共决策留痕的区别

| 项目决定确认记录 | 候选公共决策留痕 |
|---|---|
| 证明项目发起者接受哪些项目内方向 | 说明公共议题怎样进入、谁受影响、谁授权、谁异议、谁复核 |
| 约束思想归属、版本与编辑范围 | 约束公共权力、资源、执行和救济 |
| 不能代表项目外任何人 | 必须另行建立受影响者参与和合法授权 |

两种记录可以互相提供研究材料，但不能互相替代。

### 被确认的方向范围

1. 基本保障不与是否履行公共责任挂钩；逃避责任也不使基本权利消失。
2. 具备相应现实能力的成员，原则上对维持公共必要条件承担有约束力但有限的互惠公共责任。
3. 健康、年龄、照护、能力限制、心理健康、创伤、安全、隐私及其他正当理由，可以支持豁免、延期或替代承担；具体判断程序仍待设计。
4. 高于基本权利和基本保障底线、且与公共协作直接相关的互惠性公共运行权益，可以在严格相关、相称、限期、可申诉并具有恢复程序时与履责相关。
5. 具体工时、任务分配、能力判断、记录方式、非履责后果及权益清单继续保持开放。
6. 不恢复固定工时、抽签、责任积分、以拒绝劳动扣减基本保障或以单一评分固定人格的旧方案。

### 确认边界与替代关系

- 本确认部分取代 `D-015` 中“个人公共义务是否成立仍完全开放”的结论；它不取代 `D-015` 当时记录的三层不得自动跳转边界。**在 `0.1.6` 与 `D-018` 的当时口径中，这一结构展示为四个判断：公共必要性认定、公共组织与维护责任、有限互惠公共责任、具体公共责任任务义务；`D-018` 将旧第三层继续拆成原则责任与具体任务义务。**
- 后续现行状态（2026-08-20）：`D-028` 在上述历史四层中增加公共需求归属责任，当前按五个判断展示；本段保留 `PCR-5E7A91` 当时的确认范围。
- “原则上承担”不是能力登记后自动派工。具体任务仍须满足公共必要性、机构先行责任、公平分配、本人相关能力、合理条件、豁免或替代、申诉及事项适配程序。
- 本确认接受把互惠性公共运行权益与履责建立严格受限的关联，不确认具体权益清单、扣减公式、期限、记录系统或制裁方案。
- 本记录只证明 Project Aletheia 的方向决定，不是公众、受影响者、现实共同体成员或专业机构的授权。

- “任何人都可能遭遇”是本轮医疗与共同脆弱性判断的重要理由，但不单独预定所有公共需求的充分条件。
- 患者、服务使用者或受益者是否承担某种具体交互责任，须按能力、信息、可及性、必要性和比例逐项判断，不在本确认中预设。
- 公众第一责任不是每个自然人的义务总和，不从成员身份、受益、能力或公共缺口直接生成个人任务。
