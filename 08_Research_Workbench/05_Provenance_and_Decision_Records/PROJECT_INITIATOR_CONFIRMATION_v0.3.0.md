# Project Initiator Confirmation v0.3.0

## 本轮确认表达

项目发起者询问修改后的《一个公共事项，为什么要分成三步？》是否仍应发布、是否还需修改，并在没有实质内容问题时要求把当前项目升级为 `v0.3.0` 发布到已确认的公开 GitHub 仓库。

## 确认范围

1. 将截至 2026-08-25 已登记的决定、框架、草案、走查、来源和验证计划作为 Project Aletheia `v0.3.0` 公共研究快照发布。
2. 《一个公共事项，为什么要分成三步？》没有阻断再次公开的实质问题；以“反馈后探索稿”收入 `v0.3.0`，单列 `PUB-2026-003`，不覆盖 `PUB-2026-001` 的旧知乎快照。
3. 发布范围只包含项目 Markdown 文档；排除 `.DS_Store`、外部附件全文、旧压缩包、本机杂项和未授权材料。
4. 公开仓库仍为 `bbbzzzzzzzZ/Project-Aletheia`，默认分支为 `main`；另保留 `v0.3.0` 快照分支指向同一发布提交。

## 明确边界

- 这是公开研究快照的发布授权，不是对白皮书、机制总览、思想书、人生周期、司法解释或候选机制的逐句作者批准。
- `draft`、`question`、`not-ready`、`in-validation`、`proposed-unstarted`、`validation_effect: none` 等状态全部按发布前记录保留；公开本身不提升成熟度或验证状态。
- 第一原则只在十一公理与禁区范围内保持 `v1.0 / frozen`；项目版本 `v0.3.0` 不表示整套理论或制度已经完成。
- GitHub 收录 `PUB-2026-003` 不表示旧知乎问题页已经编辑、重发或与当前稿逐段一致。
- `author_review: pending` 与 `fact_check: pending` 的稿件可以作为明确标注的研究草案进入仓库，但不得倒称为作者定稿、事实结论或现实实施方案。
