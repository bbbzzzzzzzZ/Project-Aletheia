# 任务池

## 定义

任务池是等待确认、响应、执行、监督或关闭的协作事项集合。只有已经越过共同协调入口门槛的候选事项，才可以进入任务形成审查；人的需要、关系问题或服务缺口本身不进入任务池。本模块首先研究通过公共必要性审查的候选公共任务；其他协作可以借用格式，但不能因此自动取得公共能力数据或公共资源。有限互惠公共责任原则也不能只凭任务发布变成对某个人的派工。入口边界见 [`../../03_Aletheia_Framework/制度生成语法.md`](../../03_Aletheia_Framework/制度生成语法.md)。

## 任务标准格式

```text
需求来源与受影响者
目标及完成条件
必要性与不行动后果
替代方案与可撤销性
能力、人数和资源要求
时间窗口、预计负担与恢复要求
风险、禁区与紧急停止条件
提议、判断、决定、执行、监督和修复责任
报酬、公共必要性与个人承担来源
任务分支：普通自愿 / 有限公共责任 / 紧急例外
分配依据、换班、延期、替代与豁免
申诉、撤回、权限退出和数据保留
```

## 生命周期

```text
共同前段：已越过入口门槛的候选事项 → 验证 → 分类 → 任务封套

普通自愿任务：匹配 / 邀请 → 本人承诺 → 任务限定授权

有限公共责任任务：机构责任审查 → 公平分配 → 个案通知
→ 能力与条件审查 → 换班 / 延期 / 替代 / 豁免 / 异议 / 申诉
→ 个案责任决定 → 任务限定授权

共同后段：执行 → 验收 → 反馈 → 交接 → 关闭 / 重开
```

每一状态变化必须由明确角色触发并留有理由。任务关闭后，执行权限自动结束；关闭后重开或加入新任务时，须按适用分支重新审查承担依据：普通自愿任务重新取得本人承诺，有限公共责任任务重做个案义务、正当理由与救济审查；两者都须重新授权。

## 与公共能力池的匹配接口

- 任务只有完成必要性、影响、资源和共同性审查后，才可向公共能力池发起匹配；
- 对普通自愿任务，匹配结果只能形成邀请，不得自动分配人；
- 拒绝普通邀请不构成失职、权益损失或人格评价；
- 普通自愿任务只有本人明确接受后，才产生承诺范围内的执行责任；
- 有限公共责任任务不能从能力匹配直接派工，必须另外完成机构先行责任、公平分配、个案通知、能力与条件、替代、豁免、异议和申诉审查；
- 能力信息授权、联系授权、任务承诺与执行权限是四个独立步骤；
- 任务关闭或邀请权限到期后，联系资格与执行权限一并退出。

完整个人侧与任务侧接口见 [`能力池.md`](能力池.md)。

## 任务封套、责任来源与变更

无论采用哪一分支，具体对象都应是一个条件足够明确的**任务封套**，至少包含：需求来源、受影响者、目标与完成条件、不做什么、风险等级、时间窗口与最大负担、地点与移动范围、指挥与协作关系、允许访问的数据和资源、报酬与补偿、第三方影响、禁止事项、监督、申诉，以及暂停、撤回、交接和退出条件。

封套内已可合理预见的微小操作、普通分工和事先说明的调度，不需每次重建整项承诺或责任决定；激活具体操作时仍须核验当下能力、安全条件和任务限定的执行权限。

出现以下任一实质变化时，必须暂停扩张并重新说明；普通自愿任务重新取得本人承诺，有限公共责任任务重新完成个案责任与异议审查，两条分支都必须由授权程序重新授予限定权限：

- 目标、完成条件或任务对象；
- 风险等级、时间上限、地点或指挥关系；
- 数据和资源权限、报酬或成本承担；
- 对第三方的影响或本人的退出、交接与救济条件；
- 任务关闭后重开，或新增原封套未包含的任务。

制度规则、排班表、匹配结果或管理者命令均不能替代普通任务的本人承诺，也不能替代有限公共责任任务的个案程序。紧急例外必须进入独立的紧急授权程序，不能伪装成封套内的普通变更。

### 有限公共责任任务

该分支不把未作出的承诺记成“同意”。它须明确记录责任来自有限互惠原则和个案分配决定，并满足：任务必要、机构先履责、分配公平、能力适配、条件合理，换班、延期、替代、豁免、异议和独立申诉真实可用。责任决定与执行授权须由不同步骤形成；本人仍可拒绝明显越权、不安全或与封套实质不符的指令。

单次拒绝、拒绝某一条件或提出申诉均不构成逃避互惠责任。只有在长期存在多个合理选择、本人有能力承担至少一种合理份额、所有替代和救济真实可用，而本人仍无正当理由拒绝全部合理方案时，才可进入另行的责任认定程序。

### 无法亲自承诺者

当事人暂时或持续无法亲自完成承诺或参与个案审查时，应先提供可理解信息、辅助沟通、可信支持者和充足时间，尽可能使用支持性决定。明显不具备承担能力者应退出责任分配；确需代理协助表达时，只能使用范围最小、期限最短、利益冲突可见、可独立复核的替代判断，并以恢复本人参与为方向。代理不得替当事人制造高风险劳动承诺。

## 分层退出

任务机制必须分别处理：普通任务承诺前拒绝邀请、有限公共责任任务中的异议与替代申请、任务中暂停或撤回、服务关系更换、任期或授权到期、任务关闭，以及上游制度暂停或废止。

退出不取消已经发生的伤害调查、补偿、最小必要记录、数据与资源归还，也不取消已经承诺且为防止明确危险所必需的安全交接。但交接必须有对象、最小范围、时限、替代安排和申诉，机构不得因未培养替补而无限延期个人退出。

## 防造假与删工作

- 任务发布量不得直接决定预算、责任认定或管理者绩效。
- 定期审查重复、过度标准、无实际受益者和可自动化任务。
- 允许执行者和受影响者提出“任务不该存在”。
- 长期无人承担首先被视为任务条件、机构供给和必要性信号，而非个人道德失败；有限公共责任分配仍须逐人通过完整程序。

## 待验证

- 需求真实性和公共性的审查程序；
- 高风险、照护性、创造性和不可标准化任务的表示方法；
- 多任务冲突与关键系统优先级；
- 验收如何同时使用专业标准与受影响者反馈。
- 怎样记录长期无正当理由拒绝所有合理分担，并使用周期性责任当量支持公平审查，而不形成固定工时、终身总分或人格档案。
