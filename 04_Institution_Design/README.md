# 04 · 制度设计

劳动、教育、经济与政治是 Aletheia 框架的应用层。它们既把第一原则转化为机制，也反过来暴露第一原则的缺口。

本目录构成“制度白皮书”成果轨道：分别研究原则怎样进入劳动、教育、经济、政治与跨领域机制。它与公众思想书并行，但不反向取得定义人的终极生活目的的权力。

所有模块共同继承 [`第一原则`](../03_Aletheia_Framework/第一原则.md)、[`需求归属与公共需求责任`](../03_Aletheia_Framework/需求归属与公共需求责任.md)、[`责任模型`](../03_Aletheia_Framework/责任模型.md)、[`权力模型`](../03_Aletheia_Framework/权力模型.md) 与 [`反馈修正机制`](../03_Aletheia_Framework/反馈修正机制.md)。应用文档不能成为平行定义源；若现实压力测试推翻上游假设，应回写框架并记录变更。

## 当前项目级白皮书

[`Project_Aletheia_制度白皮书.md`](Project_Aletheia_制度白皮书.md) 是跨模块的当前综合入口。它以普通语言连接为什么研究、七条公众命题、需求归属与公共责任、公共决定到执行的边界、九个制度模块、评价方向和未决问题。

白皮书保持 `draft`，不成为新的术语或第一原则定义源，也不恢复旧版完整制度总纲。公式、固定参数、轮换办法和实施细则继续留在对应机制或实施层。

## 越过共同协调入口后的两套运行流程

人的需要、关系问题或服务缺口不能直接进入下列流程。它们可以由本人行动、关系调整、自愿合作、既有机构履责或权利救济回应；只有明确的结构化协作请求，或另行显示出重复、结构性、跨主体或高后果影响的候选事项，才接受共同协调入口审查。每个机制随后必须分别说明两套流程，不能把制度决定压缩成对个人的自动任务链：

```text
制度形成与修正：重复、结构性、跨主体或高后果问题
→ 识别需求来源与实质受影响者 → 比较方案并作出暂时公共决定
→ 有限试行 → 反馈、申诉与事实权力审计 → 继续 / 修订 / 暂停 / 废止

进入公共任务系统的普通自愿任务：已越过入口门槛的候选协作事项
→ 条件、权利、影响与替代审查
→ 任务封套 → 能力匹配与邀请 → 本人知情承诺
→ 分别授权 → 执行与监督 → 验收、交接、退出与修复

有限公共责任任务：公共必要性认定 → 公众承担公共需求归属责任
→ 机构先履行组织与维护责任
→ 公平分配、能力与条件审查 → 个案通知、异议与申诉
→ 换班 / 延期 / 替代 / 豁免审查 → 限定任务与权限
→ 执行、监督、交接、退出与修复
```

制度循环可以规定任务成立条件、机构职责和授权模板，但普通自愿任务仍须由本人承诺。有限公共责任原则也不能把制度规则直接变成无程序派工：具体任务仍须经过必要性、分配公平、能力与条件、通知、异议、申诉、替代与豁免审查，并另行授予限定权限。任务结果可以触发制度复核，却不能仅凭一次完成证明制度正当。每份应用稿还须明确需求来源、受影响者、责任角色、能力要求、数据与资源、监督与申诉、退出与修复及失败测试。达到共同协调入口门槛后的上游流程以 [`../03_Aletheia_Framework/制度生成语法.md`](../03_Aletheia_Framework/制度生成语法.md) 为准；本目录只展开应用分支。

个人对自身需求的表达与修订资格，不能被“其他人也受影响”取消。一项满足方案涉及他人、共同资源或公共风险时，实质受影响者取得的是对目标、取舍、边界和后果的知情、参与、异议、监督与救济资格，不是对需求者第一人称经验的所有权。

## 公共责任中必须分别说明的五项内容

应用层不得用一个模糊的“公共责任”同时指称需求归属、机构职责与成员义务：

1. **公共必要性认定**：判断一项公共需求主张是否成立，以及最低服务、可接受降级和不行动后果；它描述对象和标准，不直接产生某个人的义务。
2. **公共需求归属责任／第一责任**：需求成立后，公众对最低范围、共同成本和持续承接承担集合层责任，不能把它推回给当下求助者。公众不是每名自然人的义务总和。
3. **公共组织与维护责任**：具体决策者、出资者、公共机构、运营者或服务提供者对资金、物资、雇佣、培训、容量、预案、公平分配、信息、救济和修复承担可追溯职责。
4. **有限互惠公共责任**：有能力的共同体成员原则上对维持基本共同条件承担有约束力但有限的合理分担；正当理由可以支持豁免、延期、换班或替代。该原则已经成立，但适用成员、责任总量、任务范围、分配与后果机制仍须逐项论证。
5. **具体公共责任任务义务**：某名成员是否在特定时间承担某项有约束力任务，必须经过独立个案程序；即使成立，执行权限仍须另行授权。

第一项一旦确认某项主张属于公共需求，第二项就随需求归属成立；这一关系不再另行派责。公众第一责任仍不自动确定组织形式、成员分担、具体任务或权限。普通自愿任务由本人承诺；有限公共责任任务虽不以本人同意作为责任存在的唯一来源，也不能跳过个案程序。只有在任务必要、公众和机构先行责任可追溯、分配公平、能力适配、条件合理，且换班、延期、替代、豁免、异议和申诉均真实可用后，才可形成一项有约束力的有限任务。拒绝某一个任务、对条件有异议或暂时无法承担，都不等于逃避责任。

基本保障绝不与履责挂钩。任何责任记录只能处理已经正当成立的任务，不能单独产生派工、人格判断或基本保障后果。具体记录与计算属于下层机制，统一见 [`Incentive_System/责任积分、贡献积分与领域专业评价.md`](Incentive_System/责任积分、贡献积分与领域专业评价.md)，本框架不重复其分类、公式或参数。

## 跨制度机制

部分问题同时涉及居住、照护、教育、就业、交通、公共资源和治理，不能强行归入单一应用模块。当前新增的 [`主体社区与城市渐进可达机制`](Shared_Mechanisms/主体社区与城市渐进可达机制.md) 研究以下渐进路径：

```text
全城最低可达底线
＋主体社区的深度定制
＋关键可达走廊
＋新建与翻修中的持续扩展
```

它是待验证的机制草案，不是已确定的城市规划标准。

## 制度文档内部的三级结构

- 本目录根文件和各白皮书只写框架。
- 机制流程可在模块内新增 `Mechanisms/`。
- 参数、算法、法条和表单未来进入 `Implementation/`。
- 未验证的计量、参数和后果不得写成第一原则或白皮书结论；这类内容只在对应机制文件中保存并接受验证，历史实施稿不构成现行基线。

## 当前接口依赖

- 所有模块共享基本保障、时间主权、有限权限和反馈修正原则。
- 教育影响能力形成，但不能垄断能力认证。
- 劳动任务调用资源，但不能反向取消基本保障。
- 公共必要性认定后，先由公众承担需求归属责任；该责任必须转成可追溯的共同决定与机构职责，不直接调用个人。
- 机构必须先尽其组织与维护职责；供给失败不得被偷换成无程序派工。
- 有限公共责任是独立的个案分支，不覆盖普通自愿任务，也不把能力、成员身份或单次拒绝自动变成具体任务与权限。
- 经济交换不能购买政治权力。
- 政治决策不能垄断个人需求解释。
- 知识同时跨越教育、经济、治理和公共资源，应在后续版本评估是否独立成模块。

跨模块机制与旧候选稿统一放在 [`Shared_Mechanisms/`](Shared_Mechanisms/)，不得复制成多个相互冲突的当前版本。
